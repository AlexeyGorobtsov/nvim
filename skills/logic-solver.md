Logic Solver — логические задачи и проверка рассуждений
Логические задачи решают неверно почти всегда по одной причине: ответ угадан по ощущению и не проверен. Этот скил заменяет ощущение процедурой. Условия записываются явно, решение ищется перебором или строгим разбором случаев, готовый ответ проверяется по каждому условию отдельно.

Проверка рассуждений устроена так же. Вопрос не в том, убедительно ли оно звучит, а в том, существует ли ситуация, где все посылки верны, а вывод нет.

Примеры вызова
```text

Реши задачу. На острове рыцари всегда говорят правду, лжецы всегда лгут. А говорит: «Мы с Б оба лжецы». Кто А и кто Б?
```text

Проверь, логичен ли вывод: «Все клиенты премиум-сегмента продлевают подписку. Иванов продлил подписку. Значит, Иванов из премиум-сегмента».
Главные правила
Решай задачу, которая написана. Задача, похожая на известную, может отличаться одним словом, и ответ у неё другой. Не подставляй ответ из памяти: прочитай условие так, будто видишь его впервые.
Сначала запись, потом рассуждение. Пока условия не выписаны по одному, легко потерять одно из них или незаметно добавить своё.
Перебор надёжнее догадки. Если вариантов конечное число и можно выполнять код, перебери их все. Красивое рассуждение пригодится потом, чтобы объяснить ответ.
Ищи все решения, а не первое. Одно найденное решение не доказывает, что оно единственное. Ноль решений значит, что условия противоречивы; несколько — что условий не хватает. И то и другое нужно сказать прямо.
Проверка идёт отдельно от решения. Готовый ответ подставляется в каждое условие по очереди. Затем перечитывается вопрос: на него ли дан ответ.
Логично не значит верно. Вывод может строго следовать из ложных посылок и не следовать из истинных. Это два разных вопроса, и отвечать на них нужно отдельно.
Неоднозначность называй. Если условие можно прочитать двумя способами, скажи, какое прочтение выбрано, или реши для обоих.
Не подгоняй под ожидаемый ответ. Если получилось противоречие или несколько решений, это и есть результат.

Порядок решения
1. Выпиши условия
Пронумеруй их, держась близко к тексту. Отдельно запиши, что спрашивается. Отметь допущения, которые ты добавляешь сам (например, что каждый признак встречается ровно один раз), и проверь, есть ли они в условии.

2. Построй модель
Что является переменными, какие значения они принимают, как каждое условие записывается в виде проверки. Если условие не удаётся записать как проверку, оно понято не до конца.

3. Реши
Если можно выполнять код, используй заготовки ниже. Если нельзя, разбирай случаи вручную: таблица вариантов, каждое вычёркивание со ссылкой на номер условия, каждая ветвь доведена до ответа или до противоречия.

```python

"""Две заготовки: перебор с условиями и кратчайший путь по состояниям."""
from collections import deque
from itertools import combinations


def solve(domains, constraints, limit=10):
    """Все назначения переменных, при которых выполнены условия (не больше limit).
    domains: {переменная: [значения]}; constraints: [((переменные...), функция от их значений)].
    Пустой список — условия противоречивы; больше одного решения — условий не хватает."""
    names = list(domains)
    ready = {n: [] for n in names}
    for variables, check in constraints:
        ready[max(variables, key=names.index)].append((variables, check))
    found, current = [], {}

    def assign(i):
        if len(found) >= limit:
            return
        if i == len(names):
            found.append(dict(current))
            return
        name = names[i]
        for value in domains[name]:
            current[name] = value
            if all(check(*(current[v] for v in variables)) for variables, check in ready[name]):
                assign(i + 1)
        current.pop(name, None)

    assign(0)
    return found


def all_different(variables):
    """Условия «все значения разные» для группы переменных."""
    return [((a, b), lambda x, y: x != y) for a, b in combinations(variables, 2)]


def shortest_path(start, is_goal, moves):
    """Кратчайшая цепочка ходов. moves(состояние) -> [(название хода, новое состояние)].
    Состояния должны быть хешируемыми. None — цели достичь нельзя."""
    queue, seen = deque([(start, [])]), {start}
    while queue:
        state, path = queue.popleft()
        if is_goal(state):
            return path
        for label, following in moves(state):
            if following not in seen:
                seen.add(following)
                queue.append((following, path + [label]))
    return None
Как записывать задачи:

Расстановки. Переменная — признак («красный», «англичанин»), значение — номер дома или места. Признаки одной группы связаны через all_different.
Рыцари и лжецы. Переменная — человек, значения True (правдив) и False. Условие для высказывания: говорящий правдив тогда и только тогда, когда сказанное верно.
Проверка вывода. Переменные — простые утверждения со значениями True и False. Условия: каждая посылка и отрицание вывода. Пустой результат значит, что вывод следует. Непустой — это контрпример.
Состояния. Состояние — кортеж или frozenset. moves возвращает только допустимые ходы.
Первая задача из примеров:

```python

# А говорит: «Мы с Б оба лжецы». True — рыцарь.
print(solve({"А": [True, False], "Б": [True, False]},
            [(("А", "Б"), lambda a, b: a == (not a and not b))]))
# [{'А': False, 'Б': True}] — А лжец, Б рыцарь, решение одно
4. Посчитай решения
Одно: это ответ.
Ни одного: условия противоречат друг другу. Найди, какие именно: убирай условия по одному и смотри, когда решение появляется.
Несколько: условий не хватает. Покажи, чем решения отличаются и что у них общего. Общее можно утверждать, остальное нельзя.
5. Проверь ответ
Подставь ответ в каждое условие по номеру. Перечитай вопрос: спрашивали «кто», «сколько» или «может ли»? Если ответ найден перебором, найди и рассуждение, которое к нему приводит: человеку нужно объяснение, а не только результат.

6. Запиши ответ
По формату ниже.

Проверка рассуждений
Порядок
Найди вывод. Что именно утверждается в итоге.
Выпиши посылки. Те, что названы, по одной.
Найди скрытые посылки. Что должно быть верно, чтобы шаг прошёл, но не сказано.
Проверь каждый шаг. Попробуй построить ситуацию, где посылки шага верны, а его вывод ложен. Если получилось, шаг не проходит, и эта ситуация служит доказательством. Для выводов из «если… то», «и», «или», «не» используй перебор значений.
Проверь посылки на совместимость. Из противоречивых посылок следует что угодно, поэтому такое рассуждение ничего не доказывает.
Раздели два вопроса. Следует ли вывод из посылок — вопрос логики, на него ты отвечаешь. Верны ли сами посылки — вопрос фактов: отметь, какие из них нужно проверять, и не выдавай своё мнение о них за логический вердикт.
Читай рассуждение в самом сильном варианте: сначала пойми, что автор имел в виду, и только потом ищи разрыв. Название ошибки само ничего не опровергает: покажи шаг, который не проходит, и контрпример.

Вердикты
Вывод следует. Контрпримера нет.
Вывод следует при скрытой посылке. Назови её и спроси себя, согласился бы с ней автор.
Вывод не следует. Приведи контрпример.
Посылки противоречат друг другу. Покажи, какие.
Недостаточно определённо. Слово используется в двух значениях или утверждение читается по-разному: покажи оба прочтения.

Набор правил или требований
Те же приёмы работают для бизнес-правил и требований:

Противоречие: случай, для которого два правила требуют разного.
Пробел: случай, для которого ни одно правило ничего не говорит.
Повтор: правило, которое следует из остальных.
Если признаков конечное число, перебери все их сочетания. Перебор находит противоречия и пробелы точнее чтения.

Формат ответа
Задача:

```markdown

**Ответ:** одна строка.

**Почему:** три–семь шагов, каждый со ссылкой на номер условия.

**Проверка:** условия по номерам выполнены; решение единственное (перебрано N вариантов) или как это установлено вручную.

**Оговорки:** выбранное прочтение условия и добавленные допущения. Если их нет, раздел не нужен.
Проверка рассуждения:

```markdown

**Вердикт:** один из пяти.

**Структура:** посылки по номерам, скрытые посылки, вывод.

**Где разрыв:** шаг, который не проходит, и контрпример.

**Как починить:** какую посылку добавить или как ослабить вывод.

**Что не проверялось:** посылки, истинность которых зависит от фактов.
Пиши коротко и обычными словами. Код и ход перебора в ответ не включай, если о них не просили: человеку нужны ответ, объяснение и уверенность, что проверка была.

Другие случаи
Код выполнять нельзя. Решай вручную по тому же порядку и скажи, что проверка ручная. Если вариантов слишком много для надёжного ручного разбора, скажи и это.
Доказательство не получается. Не изображай его. Отдай то, что доказано, то, что проверено перебором на малых случаях, и то, что остаётся открытым.
Просят только ответ. Ответ и одна строка о проверке.
Просят подсказку, а не решение. Дай наводку на первый шаг и не раскрывай ответ. Следующую подсказку дай, когда попросят.
Задача из известной серии с изменённым условием. Скажи, чем она отличается от известной и почему ответ другой.
Большой текст. Выпиши утверждения и связи между ними, проверь каждый переход. В ответе перечисли противоречия и разрывы с цитатами и местом в тексте.
